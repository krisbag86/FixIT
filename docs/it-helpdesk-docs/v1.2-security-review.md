# FixIT v1.2 - przegląd bezpieczeństwa 2026-08-19

Przegląd wykonano na aktualnym `origin/main` po wcześniejszym merge PR #9. Historyczny branch `codex/v1.2` nie został ponownie scalony; zachowano nowszy portal zgłaszającego, refaktoryzację warstw danych i późniejsze testy.

## Zamknięte problemy

1. CSP: żądanie jest ograniczone do 16 KB przed parsowaniem, raporty są walidowane przed zużyciem limitu, klienci mają osobne limity, a globalny bezpiecznik nie pozwala na nieograniczoną telemetrię.
2. Reporting API: paczka przekazuje każdy poprawny raport, maksymalnie 10 na żądanie; adresy URL tracą query stringi i znaki sterujące przed wysłaniem do Sentry.
3. Upload: całe multipart request ma twardy limit, komentarz musi należeć do tego samego ticketu, użytkownik bez uprawnień nie może podpiąć pliku do notatki wewnętrznej, a plik jest sprzątany po błędzie metadanych.
4. Widoczność: eventy `INTERNAL_NOTE_CREATED` i załączniki komentarzy wewnętrznych nie trafiają do widoków bez uprawnień agenta.
5. CSV: znaczniki formuł są neutralizowane także po białych znakach; oba rodzaje końca linii wymuszają poprawne cytowanie.
6. Setup token: aktualna implementacja konsumuje nieprawidłowy token przed kosztownym hashowaniem; regresja potwierdza brak wywołania PBKDF2.
7. Testy E2E: osobny kontekst admina usuwa współdzielenie cookie z reporterem, test czeka na odpowiedź Server Action, a limiter jest pomijany tylko dla `FIXIT_E2E=true` poza produkcją.
